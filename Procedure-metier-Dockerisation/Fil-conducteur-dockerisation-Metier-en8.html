File Conducteur – Dockerisation API Métier .NET 8

Ce document explique l’imbrication complète : Code → Dockerfile → Image → Compose → Conteneur.

1. Code .NET 8 – API Métier

Structure typique :

EPARVIER.Metier/
  ├─ Controllers/
  ├─ Program.cs
  ├─ EPARVIER.Metier.csproj
  └─ Dockerfile

Le Dockerfile est la recette pour transformer ton projet en image Docker.

2. Dockerfile – Construction de l’image

Exemple pour une API .NET 8 :

FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS base
WORKDIR /app
EXPOSE 8080

FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY . .
RUN dotnet restore
RUN dotnet publish -c Release -o /app/publish

FROM base AS final
WORKDIR /app
COPY --from=build /app/publish .
ENTRYPOINT ["dotnet", "EPARVIER.Metier.dll"]

Build de l’image :

docker build -t eparvier-metier:2026-07-17 .

Résultat : une image locale eparvier-metier:2026-07-17.

3. docker-compose.yml – Architecture du module

Localisation KING‑AO :

/opt/KING-AO/modules/EPARVIER/compose/docker-compose.yml

version: "3.9"

services:
  eparvier-metier:
    image: eparvier-metier:2026-07-17
    container_name: eparvier-metier
    ports:
      - "5001:8080"
    networks:
      - kingao-net
    environment:
      - ASPNETCORE_ENVIRONMENT=Production

networks:
  kingao-net:
    external: true

Le compose n’effectue pas le build : il utilise l’image déjà créée.

4. Lancement du module

Commande KING‑AO :

docker compose -f /opt/KING-AO/modules/EPARVIER/compose/docker-compose.yml up -d

Ce que fait up -d :

  • Lit le fichier compose
  • Vérifie l’image eparvier-metier:2026-07-17
  • Crée le conteneur
  • Le connecte au réseau KING‑AO
  • Lance l’API métier

5. Vue d’ensemble – Imbrication complète

Code .NET 8 (EPARVIER.Metier.csproj)
        │
        ├─ Dockerfile
        │    └─ docker build → image eparvier-metier:TAG
        │
        └─ docker-compose.yml (module EPARVIER)
             └─ docker compose up -d
                  └─ conteneur eparvier-metier

Règle d’or : si le PATH du compose est faux, KING‑AO ne voit pas le module.

Architecture KING-AO complète

Vue d’ensemble des modules, de leurs rôles et de leurs connexions dans l’architecture dockerisée.

1. Modules principaux

NGINX        → Reverse proxy / entrée HTTP(S)

2. Flux de requêtes

Client (navigateur)
    │
    ▼
NGINX (reverse proxy)
    │
    ├─> PORTAL (front web)
    │       │
    │       ├─> EPARVIER (API métier)
    │       └─> KINGDOMAINE (API référentiels)
    │
    └─> APIs directes (EPARVIER / KINGDOMAINE) si besoin

3. Réseau Docker – kingao-net

Tous les services sont connectés au même réseau :

networks:
  kingao-net:
    external: true

Chaque service dans son compose :

services:
  nginx:
    image: kingao-nginx:TAG
    networks:
      - kingao-net

  portal:
    image: kingao-portal:TAG
    networks:
      - kingao-net
